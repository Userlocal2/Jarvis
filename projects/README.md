# Projects Index

`projects/` содержит проекты.

## Rules

- В `projects/` должны лежать только проектные директории и связанные с ними файлы.
- `projects/` сам по себе не должен быть отдельным git-репозиторием.
- По умолчанию каждый проект в `projects/<name>/` должен иметь собственный git-репозиторий, если при его создании явно не указано иное.
- По умолчанию каждый проект должен собираться, запускаться и тестироваться в своём собственном контейнере, если явно не указано иное.
- По умолчанию проектные скрипты, включая тесты, должны выполняться внутри контейнера проекта.
- Если проекту нужна база данных, она должна размещаться на отдельном сервере. Параметры такого сервера нужно запрашивать у администратора.

## Project Registry

- `PROJECTS.yml` в этой директории является канонической шпаргалкой по всем проектам.
- При любом изменении проекта нужно обновлять `projects/PROJECTS.yml` в той же сессии работы.
- Состав полей может быть специфичным для конкретного проекта, но любая полезная и актуальная информация о проекте должна поддерживаться здесь в актуальном состоянии.
- Если информация в `PROJECTS.yml` устарела, это считается задачей на исправление.
